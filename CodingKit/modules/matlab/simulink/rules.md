# 模块目录与文件规则

本文件只规定目录、文件名、记录字段和检查结果。算法选择与架构说明分别放在模块 README 和 docs 中。

## 1. 原始模块按功能建目录

可复用积木放在model/lib/<module_name>/。完整算法App按闭环使用的角度/速度来源分类：

- 使用位置/速度反馈的App放model/app_models/Sensor/<module_name>/；当前仿真反馈App也归此类。
- 使用观测器或估算角度/速度的App放model/app_models/Sensorless/<module_name>/。
- 仅用于监测和误差对照的对象真实角度不作为分类依据。Sensorless表示无转子位置传感器，不表示取消电流采样。

学习、论文复现和第三方示例分析放在 `model/studies/`；其中开始实现的功能模块沿用下述模块目录规则。

组件独立测试台随lib积木保留。App与lib功能目录的模型SLX均放各自src，过程模型放build_process，外部参考模型放ref。Sensor、Sensorless是分类目录，具体算法开始实现时才创建功能模块目录。

可复用观测器及其独立测试台归model/lib；Sensor和Sensorless App通过库链接引用，不在App下维护观测器实现副本。

工程顶层目录只保留 `model/` 和 `docs/`。未来模块只记录在建设计划中，开始搭建时再创建模块目录。

lib 的功能目录按功能和算法命名，中文名最多十个字，现有 `math` 保留。观测器的功能目录统一放在 `model/lib/观测器/`。App 与 studies 的功能目录继续使用小写英文、数字和下划线，以字母开头。

## 2. 每个模块必须包含以下文件和目录

```text
<module_name>/
├── README.md
├── src/                    主模型和独立测试模型
│   └── <ModelName>.slx      模型创建后放在这里
├── build_process/          模型搭建过程
├── waveform_analysis/      波形与分析
├── ref/                    参考资料
├── parameter/              配置、输入、过程、输出和示波器通道说明
└── docs/                   原理、公式推导及模型对应
```

六个子目录各放一份 README.md。没有内容时写明“暂无”，不能省略目录。

## 3. 模型文件命名

新建 `.slx` 的文件名只使用英文字母、数字和下划线，以字母开头。模型文件名与 Simulink 模型名一致。

- `model/lib/<module_name>/src/`中的可复用库模型不带`Test`后缀；用于验证的模型以`Test.slx`结尾。
- 同一 lib 可保留多组库模型和验证模型。每份非 Test 库 SLX 至少有一份与实际发布接口对应的 `.slxp`，同放模块 `src/`。不同的独立发布接口分别打包。
- 修改发布接口、默认参数、采样或算法后，重建受保护模型。比较库链接与受保护 Model block 的同工况输出，并记录端口、维度、数据类型、采样、配置、目标平台及 SHA-256。执行步骤见[受保护模型维护计划](docs/plans/PROTECTED_MODEL_PLAN.md)。
- `model/app_models/`中的App模型本身用于运行，不带`Test`后缀。
- 验证模型通过库链接调用对应模块；模型改名时同步内部模型名、加载回调、脚本入口、README和路径链接。

## 4. 模块 README 的固定栏目

模块 README 必须有 `用途`、`文件`、`接口`、`参数`、`验证` 五个二级标题。

- 文件表字段：`路径`、`状态`。状态只用 `未创建` 或 `已创建`；`已创建` 的路径必须存在。
- 接口表字段：`名称`、`方向`、`单位`、`类型`、`采样周期`。
- 参数表字段：`名称`、`单位`、`定义文件`。
- 验证栏目列出测试模型/脚本路径和结果记录路径；未执行时写 `未执行`。

模型尚未创建时，未确定的接口和参数字段统一写 `待定义`。

## 5. 搭建过程文件位置

本模块的搭建步骤、块连接记录、参数设置记录和过程模型放在 `build_process/`。该目录 README 列出记录文件的相对路径。

## 6. 波形与分析文件位置

本模块的波形数据、图和分析记录放在 `waveform_analysis/`。每份分析记录必须包含 `模型文件`、`参数文件`、`采样周期`、`求解器/步长`、`工况`、`数据文件` 六个字段；路径相对于模块目录填写。

## 7. 参考资料文件位置

本模块的参考模型、文档、截图和来源索引放在 `ref/`。`ref/README.md` 按 `资料`、`来源` 两列登记；来源填写原始路径或 URL。当前没有资料时写 `暂无`。

## 8. 参数文件位置

每个模块使用单数目录名 `parameter/`，参数定义、默认值和参数/信号说明均放在其中。工程根目录不设置统一参数目录。

每个已建模块的`parameter/`至少包含一个可执行的`*_parameters.m`参数入口。控制器、电机和默认测试工况的可配置数值在这些M文件中定义，由模型初始化函数加载到模型工作区；`parameter/README.md`链接实际入口，写明重新加载参数的方法。引用其他模块的参数时，在本模块入口组合或覆盖对应结构体，不把默认数值重复存入SLX块。

`parameter/README.md` 必须包含 `配置参数`、`输入信号`、`过程变量`、`输出信号`、`Scope 通道` 五个二级栏目；暂无内容的栏目写 `暂无`。

- 配置参数表列出名称、默认值、单位、含义，并链接定义文件。
- 输入、过程、输出表列出名称、单位、类型或状态初值、来源/所在块及计算或用途。
- Scope 表按实际通道顺序列出序号、名称、来源、单位/记录类型、观察内容。没有送入 Scope 的变量不得写成已有通道；没有 Scope 时写 `暂无`。

电机、板卡与场景参数随对应模块放入自己的 `parameter/`，引用其他模块的定义时使用文件路径，不另建顶层参数副本。

## 9. 文件表中的路径

模块 README 及六个子目录 README 的本地文件链接使用相对路径。文件表中标为 `未创建` 的模型不生成可点击文件链接；已有文件链接不得指向不存在的路径。

工程级验证说明、脚本入口说明和公共接口说明分别放在 `docs/validation/`、`docs/scripts/`、`docs/interfaces/`。工程根目录不再设置这三个同名目录。

## 10. 模块原理与公式文档

每个lib和App功能模块都设置自己的`docs/`。同一模块内有多份SLX时，在该模块文档中分别说明，不按SLX再建重复目录。

`docs/`中保留两份Markdown文件：

- `README.md`：链接本目录的`公式推导.md`及对应模型、参数和运行说明。
- `公式推导.md`：从原理推到模型所用公式，说明符号/单位、实际离散或代数实现，以及公式与块、状态、参数的对应关系；公式使用LaTeX，行内用`$...$`，独立公式用`$$...$$`。

模块根README链接`docs/README.md`；两份文档随模型实现同步维护。

## 11. 变更后的检查

新增、删除、移动或更名文件后：

- 更新父级 README 的入口链接。
- MANIFEST.json 的 `file_count`、`directory_count`、`readmes` 统计随工程交付的文件和目录，排除 Git 忽略的本地生成结果；目录数量包含工程根目录。
- Markdown 本地链接检查必须为 0 个错误。
- `git diff --check` 必须通过。

## 12. Agent操作模型窗口

- 同时只打开当前模型的编辑器窗口；切换模型前保存并关闭前一个。
- 只展开当前正在检查的子系统或Scope，检查完成后关闭；批量仿真不打开额外窗口。
- 本次操作结束后，保存并关闭本次打开的Simulink窗口，保留MATLAB主窗口。

## 13. 工程符号约定

- [符号定义表](docs/userdocs/符号定义表.md)是本工程的符号、定义和缩写依据，来源为《永磁同步电机无位置传感器控制》印刷VII–XIX页。
- 工程公式、接口说明、参数说明和Scope通道说明使用表中已有物理量时，采用对应符号与定义，保留大小写、上下标及估计/参考标记，不把同一符号重新定义为另一物理量。
- 符号表以用户维护的最新版本为准，不用PDF重提取结果或历史转录稿覆盖用户修订。Agent不得擅自改写表内符号、描述和单位，不合并重复条目、不补填空白单位；原表空白不作为无量纲声明。
- MATLAB/Simulink中的工程标识与原书符号不同时，在所属模块`parameter/README.md`列出“原书符号、工程标识、工程单位、单位换算”四列映射；工程使用H而原书为mH等情况，写出实际换算关系，不修改原表。
- 原表未收录的量在所属模块`parameter/README.md`另行定义符号、含义和单位，不追加到原书转录表中。
