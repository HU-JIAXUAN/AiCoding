## 2. lib保持积木边界

基波链路保持 `电压/电流 → 物理量观测 → 相位提取/PLL → θe、ωe、valid`。SMO、EMF与磁链可在内部引用同一个AngleTracking库块；PLL本身不消费电机真实角度，也不能单独证明无位置估计成立。

HFI链路增加实际激励：`注入请求 → 调制/逆变器 → PMSM → 电流采样 → 高频提取/同步解调 → 轴角度`。高频电流必须由Plant对注入电压的响应产生。真实θ只在Plant内部决定电感/磁链及在测试记录里计算误差，不能进入观测器，也不能直接生成所谓“测得的解调信号”。

凸极轴角度具有π歧义。接口与波形分别记录轴角度是否可信、极性是否已识别及最终完整电角度是否可用；仅轴线收敛时不放行转矩闭环。常参数Ld/Lq对象能验证轴线响应，不能验证依赖磁饱和的正负脉冲极性辨识。

lib只维护算法、状态、复位和质量诊断。电机实例、母线、注入限幅、采样/计算延迟、启动阶段与失锁处理由App组合；App引用库链接，不复制算法实现。参数继续放各模块 `parameter/*_parameters.m`。

## 4. App组装要落实的连接

电压有三个不同位置：PI请求、最终执行电压、观测器取得的电压。观测器使用采样或重建的执行电压，不能把限幅前PI请求当实际电压。当前SensorlessFOC从VoltageStage取得理想最终相电压，经Clarke后送SMO；这能验证理想MIL，但没有证明硬件能够取得同样准确的电压。

后续在现有Measurement/VoltageStage中组合“最终占空比×测得母线电压”的重建支路，并与Plant实际执行支路分开。延迟、死区、器件压降和测量偏差只在相应支路引入；复用已有inverter/timing/deadtime，不另造一套PWM链。记录电流和电压的采样时刻、所属执行区间及必要预测量。

HFI与基波观测器并行，先各自取得在线资格，再进入重叠速度区融合。书中角度加权式在本工程按包角差实现，例如 `θ=wrap(θlow+w·wrap(θhigh−θlow))`，避免±π附近直接平均跳变；w的具体速度阈值、变化速率及迟滞在App参数定义。正反转使用速度幅值选择区域，带符号速度仍供控制/预测。

融合期间同时处理电流参考坐标、PI积分状态和最终电压，不能只画两条重合角度。记录相位差、融合权重、两路valid、注入电压、电流、转矩、限压状态及电流PI状态；高速撤除HFI后，低速重新开启时要重新确认轴线/极性条件。
