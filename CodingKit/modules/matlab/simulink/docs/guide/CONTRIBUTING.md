# 维护说明

工程约束统一维护在 [rules.md](../../rules.md)。本文说明文件、记录和验证的维护动作；修改前先读取工程规则及当前受影响内容。

## 修改范围

先读根 README、相关接口/参数和已有结果。只更新直接受影响的组件与说明，不为局部增益调整建立完整架构流程。端口、单位、状态所有者或部署边界改变时再记录 ADR。

## README 与目录

根 README 维护当前可用范围、主要目录和入口；有独立用途的目录写清“放什么、与谁协作、从哪里进入”。不要求未来每个目录都复制相同制度，不继续为了凑层次建立空目录。

新增、移动或更名资产时同步父级导航与链接，并核对 manifest 统计。复用功能放在model/lib/<module_name>，完整算法按位置反馈放在model/app_models/Sensor/<module_name>或Sensorless/<module_name>，建设顺序以 docs/plans/IMPLEMENTATION_PLAN.md 为准；只在开始搭建时创建模块目录。

## 参数与模型

参数有来源、单位与适用范围；字典/脚本/base workspace 不重复维护互相冲突的数值。小积木用清晰端口，公共接口不使用没有定义的 u1/y1/gain2。

模型名可用 PascalCase，普通 MATLAB 函数按工程既定规则一致命名；目标/板级目录使用稳定身份，版本只记录在 manifest、文档和变更记录。禁能、复位、限制与采样时间属于组件合同。

## 验证与结果

文档整理检查链接、目录与内容一致性；模型出现后按变化做有意义的组件/闭环检查。共同场景、指标与最终参数随结果保存，不以单张 Scope 图宣称性能。

模型、生成代码、C2000 构建/PIL、ISR 时序与实机分别给出证据。修改板级适配时重新检查资源所有权和执行链，不从另一块板继承时序结论。

## 派生输出

不提交 slprj、slxc、临时自动保存或未审查的大体积派生结果。可维护的 slx/sldd 属于源资产；必要报告保留配置与摘要，大波形按实际需要归档。变更记录在形成里程碑或提交时汇总，本轮框架变更记录在模块 CHANGELOG。
